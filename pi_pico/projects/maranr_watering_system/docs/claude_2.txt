**About the patterns as written**

1. **Step 2, `.*_venv/`: glob or regex?** You describe it as "one dot, some chars, underscore, venv". That reads as a glob, where `.` is a literal dot and `*` means "any chars". In a regex, `.*` means "anything", so the leading literal dot would be lost. My suggestion is to make the directory filter glob-based and test it against each directory name in the path separately (e.g. `.mws_venv`). Then the trailing `/` isn't needed, because a name test already means "the whole directory name". One consequence: as a glob, `.*_venv` matches `.mws_venv` but not `mws_venv`. Is that what you want?
A: yes a glob-based matching would work fine

2. **Step 4, `*_V\d+\.py$` isn't a valid regex.** A leading `*` is a regex error. I'd use `_V\d+\.py$` and run it with `re.search`, which finds a match anywhere, so no leading `.*` is needed. Your step 4 patterns would then always use search-anywhere-in-the-filename, with `$` anchoring the end. OK?
A: yes, in addition I would expect to be able to specify '^' for 'at the start' and other such. If the filter supports any RE pattern, that would be good - I assume that is an easy to implement behavior. I just am trying to minimize the complexity of any regex patters and not wind up having the program to be implemented using a bunch of complex patterns -- when the program could do the same job more simply, say in a different step (for example)

3. **Case sensitivity.** You listed both `*JUNK*.py` and `*junk*.py`, so I take it matching is case-sensitive. That leaves `*Junk*.py` uncaught. Options: (a) always case-sensitive, and you list each variant; (b) a separate case-insensitive pattern list. I'd use `fnmatch.fnmatchcase`, which behaves the same on every OS, rather than plain `fnmatch`, which is case-insensitive on Windows. Which do you want?

(but is there a simple way to say 'case insensitive'? I'm not aware of one.)
